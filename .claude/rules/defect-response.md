# 欠陥への対応ルール

## 原則

**本質的な欠陥は、指示された作業範囲の外で見つけても、その時点で直す。**

理由: 欠陥は発見した瞬間が最も安く直せる。再現手順・原因・周辺コードの理解が揃っているのはその時だけであり、記録して先送りした欠陥は次に触るときに再調査から始まる。

実例（[ADR-026](../../docs-spec/adr/ADR-026-gui-audio-path.md)）: GUI E2E の整備という作業の途中で、GUI 同士で音声が流れない原因が 3 つ直列に並んでいることが判明した。どれも当初のスコープ外だったが、1 つでも残せば音声は流れないため、その場で 3 つとも直した。同時に見つかった「参加者が作成者と違うルームコードを表示する」欠陥も同じ理由で直した。

## 即座に直す対象

指示の有無を問わず直す。

| 分類 | 例 |
|------|-----|
| 利用者が観測できる機能不全 | 音声が流れない、参加者が別のルームコードを表示する |
| 保存した状態が効かない | 設定した入力デバイスが起動時に無視される |
| 測定値を装った定数 | `packet_loss_rate: 0.0 // TODO`（詳細は `traceability.md`「指標は定数化させない」） |
| 仕様と実装の矛盾 | `docs-spec/` が正。実装を直す（仕様が誤っている場合は新規 ADR を書く） |
| 同一原因の重複 | 同じ計算が 3 箇所に複製されており、1 箇所だけ直しても再発する |
| 秘匿情報・ライセンス違反 | `source-available.md` 参照 |
| 事実と異なるコメント・ドキュメント | 「`enqueue_playback` の排出速度がケイデンスを決める」が実際は何も律速していなかった等 |

### 直すときの作法

1. **検証を同時に書く。** テストのない修正を「直した」と報告しない
2. **要求として立てる。** REQ-ID を振り、テストに `Verifies:` を付け、`traceability.md` を再生成する（`traceability.md` 参照）
3. **別コミットにする。** 元の作業と混ぜない（`git-workflow.md`）
4. **設計判断を伴うなら ADR を書く。** ADR は追加のみ
5. **報告する。** 何を直したか・なぜ本質的か・どう検証したかを述べる

## 直さずに記録する対象

範囲を決めるのは利用者である。以下は**記録して報告し、指示を待つ**。

| 分類 | 対応 |
|------|------|
| 製品要件の判断が必要（機能の追加・削除・仕様変更） | Plans.md の「判断待ち」に記録し、推奨案を添えて確認する |
| アーキテクチャの大きな変更が必要 | 同上。ADR の草案を示して確認する |
| 実機・実回線・外部サービスが無いと検証できない | Plans.md の「実環境待ち」に記録する |
| 再現も検証もできず、推測でしか直せない | 記録に留める。検証手段が無いまま推測で入れない |

判断の基準は **検証できるか** と **可逆か** である。テストで検証でき、間違っていても元に戻せるなら直す。どちらも満たさないものは記録する。

## 禁止

1. **黙って放置しない** — 「スコープ外だから」を理由に、報告もせず見過ごしてはならない
2. **TODO だけ残さない** — コメントは実行されない。直すか、Plans.md に記録して報告するかのどちらかにする
3. **テストを弱めて通さない** — 欠陥を知りながら閾値を緩める・アサーションを外すことを禁じる（`test-quality.md`）
4. **ついでに広げない** — 直すのは欠陥そのものと、その検証に必要な範囲まで。整形・改名・最適化を混ぜない

❌ 悪い例

```
（レベルメーターの配線を調べている途中で、保存したデバイス設定が
  起動時に読まれていないことに気づいたが、今回の作業と関係ないので触らなかった）
```

❌ 悪い例

```
ジッタバッファの挙動が怪しいので、しきい値を 0.05 → 0.5 に緩めてテストを通した。
```

⭕ 良い例

```
レベルメーターの配線を追う過程で、保存したデバイス設定が起動時に読まれていない
ことが判明した（AudioState が config を参照していない）。表示だけが復元され、実際の
キャプチャは既定デバイスのままだった。

新規の REQ-AUD-0NN として要求を立て、AudioState::from_config を追加して単体テストで
検証し、別コミットにした。
```
